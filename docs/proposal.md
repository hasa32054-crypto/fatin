# مقترح تبنّي «فطن» — للجهات الحكومية والقطاع المالي والاتصالات

**مقدّم المقترح:** حسان عبدالله الينبعاوي · ثانوية الموهوبين التقنية · تعليم جدة
**المشروع:** فطن · سندك الذكي ضد الاحتيال — `hasa32054-crypto.github.io/fatin`
**ملاحظة:** فطن مشروع طالب مستقل، وليس تابعًا لأي جهة حكومية أو بنك حتى الآن.

---

## 1. المشكلة
رسائل ومكالمات الاحتيال (انتحال البنوك والجهات الحكومية، الشحنات الوهمية، «القريب في ورطة»، طلب رمز التحقق) تستهدف الجميع، والأكثر تضررًا: **كبار السن، وذوو الإعاقة، والعمالة الوافدة** — لأن التحذير ما يوصلهم بلغتهم أو بالطريقة اللي تناسبهم.

## 2. الحل
تطبيق مجاني يكشف الاحتيال ويدرّب عليه:
- **يفحص** الرسالة والرابط والرسالة الصوتية والرقم، ويشرح السبب بكلام بسيط.
- **يقرأ الرابط** بأمان من الخادم: وين يوصل، هل يطلب بطاقة أو رمز، كم عمر الموقع، وهل هو رسمي.
- **يدرّب** بمكالمات واقعية بصوت ذكاء اصطناعي، وفطن ينبّه أثناء المكالمة، ونتيجة بالثواني يتحدّى فيها المستخدم أهله (#تحدي_فطن).
- **يوصل لكل فئة:** صوت للمكفوفين، اهتزاز ووميض للصم، وضع بسيط لكبار السن، و10 لغات للوافدين.
- **بلاغ جاهز** يكتبه فطن للمستخدم، ولوحة أسرة تنبّه الأهل بدون كشف نص الرسائل.

| المجال | الدليل |

| الأمن السيبراني | مواءمة ذاتية مع «معيار التطوير الآمن للتطبيقات» — `docs/nca-compliance.md`، و**49 فحصًا أمنيًا آليًا** قبل كل نشر |
| حماية البيانات | موافقة صريحة، تقليل البيانات، «احذف بياناتي»، خريطة بيانات — `docs/data-map.md` |
| أخلاقيات الذكاء الاصطناعي | مواءمة مع مبادئ سدايا السبعة — `docs/ai-ethics.md` |
| إمكانية الوصول | WCAG 2.2 AA — `docs/wcag-report.md` |
| التكامل | API مفتوح (OpenAPI 3.1)، SDK بدون إنترنت، تطبيق مصغّر، موجز تهديدات STIX 2.1 — `docs/api.md`، `docs/integration.md` |
| السيادة | حزمة خادم داخل المملكة (Oracle جدة) مع خيار نموذج ALLaM — `server/saudi/` |

## 4. طرق التبنّي (من الأخف للأعمق)

| الخيار | وش تسوي الجهة | المدة التقديرية |
|---|---|---|
| **أ. توعية** | تنشر رابط فطن وتحدّي #تحدي_فطن في قنواتها | أيام |
| **ب. موجز التهديدات** | تستورد `/v1/feed.stix` في منصتها كمؤشر إضافي | أسبوع |
| **ج. خدمة فحص** | تربط `/v1/check` أو SDK في تطبيقها أو بوت الواتساب | 2–4 أسابيع |
| **د. تطبيق مصغّر** | تضمّن فطن داخل تطبيقها الشامل (مثل توكلنا) بهويتها | 4–8 أسابيع |
| **هـ. تبنٍّ كامل** | تستضيفه على بنيتها وتطبّق «كود المنصات» وهويتها | حسب الجهة |

## 5. تجربة تشغيلية مقترحة (90 يوم)

| المرحلة | الأسابيع | المخرجات |
|---|---|---|
| تجهيز | 1–2 | نقل الخادم لبيئة الجهة أو جدة، مفتاح شريك، مراجعة أمنية من الجهة |
| تجربة محدودة | 3–8 | 300–1000 مستخدم من الفئات المستهدفة، عبر جمعيات ذوي الإعاقة ومراكز كبار السن ومكاتب الاستقدام |
| قياس | 9–11 | دقة على رسائل حقيقية مجهولة الهوية، رضا SUS، تحسّن الكشف قبل/بعد التدريب |
| قرار | 12 | تقرير نهائي وتوصية بالتوسع أو التعديل |

**مؤشرات النجاح:** تحسّن قدرة المستخدم على الكشف ≥ 30% · رضا SUS ≥ 75 · إنذار خاطئ ≤ 5% على الرسائل الحقيقية · صفر حوادث تسرب بيانات.

## 6. التكلفة
- الكود موجود ومكتمل. التشغيل الحالي على الخطط المجانية (Cloudflare، GitHub Pages) + اشتراك صوت بسيط.
- الخادم السعودي يشتغل على الطبقة المجانية لـ Oracle Cloud (جدة).
- عند التوسع: تكلفة الصوت والذكاء الاصطناعي حسب الاستخدام — أو صفر بنموذج ALLaM والسمع المحلي على خادم الجهة.

## 7. المطلوب من الجهة
1. نقطة تواصل فنية.
2. بيئة استضافة أو موافقة على الاستضافة في جدة.
3. (اختياري) عينة رسائل احتيال حقيقية **مجهولة الهوية** لقياس مستقل.
4. اتفاقية تحفظ ملكية المطوّر الفكرية (`docs/ownership.md`).
